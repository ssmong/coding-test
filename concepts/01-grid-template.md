# 격자 문제 고정 세팅

## 언제 쓰나

NxN/NxM 격자 위에서 탐색·시뮬레이션하는 모든 문제. 세 가지(인덱싱·경계 체크·방향 벡터)를 매번 같은 꼴로 박아두면 시험장에서 생각할 자원을 문제 로직에 집중할 수 있다.

### 방향 번호 ↔ 이동량 표 (회전 버전)

| d | 방향 | dr[d] | dc[d] |
|---|---|---|---|
| 0 | 우 | 0 | +1 |
| 1 | 하 | +1 | 0 |
| 2 | 좌 | 0 | -1 |
| 3 | 상 | -1 | 0 |

```
    0:우
  3:상   1:하     ← 시계방향 순환
    2:좌
```

시계방향으로 번호가 올라가므로 **"오른쪽 회전 = +1"** 이 성립. `(3 + 1) % 4 == 0`이 상→우로 자연스럽게 순환시킨다.

### 4방향 외의 이동 집합

**8방향 (대각 포함)** — 상하좌우 + 대각 4개:
```python
DR8 = (-1, -1, -1,  0, 0,  1, 1, 1)
DC8 = (-1,  0,  1, -1, 1, -1, 0, 1)
```

**나이트/말 (L자, 1600)** — 한 축 ±2, 다른 축 ±1, 부호 자유 → `2×2×2 = 8`가지:
```python
HDR = (-2, -2, -1, -1,  1,  1,  2,  2)
HDC = (-1,  1, -2,  2, -2,  2, -1,  1)
```
검산: 각 쌍이 `|dr| + |dc| == 3` 이고 한쪽이 2면 빠진 것 없음. 쓰는 법은 4방향과 동일 (`for d in range(8)` + 경계 체크).

## W·H, x·y가 헷갈리는 이유 (행/열 혼동의 근원)

두 좌표계가 충돌하기 때문. **둘 다 맞는데 순서가 반대다.**

| | 직관 (수학/그래픽스) | 2D 배열 인덱싱 |
|---|---|---|
| 표기 | 점 `(x, y)` | `grid[?][?]` |
| 첫 번째 | `x` = 가로 = `W` | **행 = 세로 = `H`** |
| 두 번째 | `y` = 세로 = `H` | 열 = 가로 = `W` |
| 순서 | x(가로) 먼저 | **행(세로) 먼저** ← 역전 |

직관은 "가로 먼저"인데 배열은 "행(세로) 먼저"라, `grid[x][y]`로 쓰면 `grid[가로][세로]` = 전치 → 비정방 격자서 IndexError.

**처방: 격자 문제에선 `x/y`를 버리고 `(행 r, 열 c)`로 써라.**
```python
H, W = len(grid), len(grid[0])   # H=행 수, W=열 수
for r in range(H):
    for c in range(W):
        grid[r][c]               # 첫 인덱스=행, 고민 불필요
```
`r`은 명백히 행 → 첫 인덱스 → `H`로 제한. `c`는 열 → `W`로 제한.

**W/H 판별:** 입력이 "가로 W, 세로 H, 그다음 H줄에 W개씩"이면 → 행 H개, 한 행에 열 W개 → `grid`는 `[H][W]`. *H = 몇 줄, W = 한 줄 길이.*

## 함정

- **`grid[a][b]`의 첫 인덱스 `a`는 언제나 "행".** 입력을 `[행][열]`로 읽었으면 `dist`·경계·도착의 **첫 축도 행으로 통일**하라 → `dist[r][c]`, `0<=nr<H and 0<=nc<W`, 도착 `(H-1, W-1)`. 이러면 `grid[nr][nc]`가 자연히 맞아 전치 버그가 원천 차단. **열을 `x`(첫 축)로 부르면** `grid[x][y]`가 `grid[열][행]` 전치가 되어 비정방 격자서 IndexError (1600에서 발생). 입력을 transpose해서 맞추는 건 실수 지점만 늘리니 비추 — 축 이름을 맞춰라.
- **1-indexed vs 0-indexed는 문제 지문에 맞춰라.** 지문이 "r행 c열" 1-based인데 0-indexed로 받으면 매 입력마다 `-1` 보정이 쌓여 off-by-one 지옥. 3190·16236 등은 1-based.
- **거리·방문 배열은 0-indexed로 두고 입력만 변환**하는 것도 가능하지만, 본 코드 안에서 인덱싱이 두 종류 섞이면 혼란. 한 문제에선 하나로 통일.
- **방향 벡터 배치 순서는 목적에 따라 다르다.** BFS는 아무 순서 OK, **회전 문제는 반드시 시계방향 순**으로 배치해야 `±1 % 4` 공식이 성립. 상어·뱀·청소기 계열 필수.
- **입력이 시작 방향 `d`를 주면 DR/DC 배열의 방위 순서를 그 인코딩에 맞춰라.** 로봇청소기·자율주행(14503류)은 `d`: **0북/1동/2남/3서**. 배열을 다른 순서(예: 북서남동)로 두면 시작 방향이 뒤바뀜 — 특히 `d=1/3`(동·서)에서만 틀려 **북/남 예제는 통과하고 채점서 터진다.** 정합: `DR=(-1,0,1,0)`, `DC=(0,1,0,-1)` (북동남서) + 좌회전 `(d+3)%4`, 우회전 `(d+1)%4`. **좌/우로 시작하는 테스트 필수.**
- **"왼쪽부터 훑어 갈 수 있는 칸을 찾으면 전진"류 시뮬레이션은 찾자마자 `break`.** 청소기·자율주행에서 `for d in range(4)` 안에서 이동 후 `break`를 빼면 한 스텝에 여러 번 전진·회전이 겹쳐 과다 처리. 그리고 후진/정지 판정은 **원본 격자(벽 여부)**를 보라 — `visited`(방문 여부)로 벽을 판정하면 벽은 항상 미방문이라 정지가 안 걸린다.
- **이동 집합이 여러 개면 벡터 세트를 분리.** 1600은 일반 이동(4방향, `DR/DC`)과 말 이동(L자 8방향, `HDR/HDC`)이 공존 → 두 세트를 따로 두고, **말 이동만 상태 `k` 소모**(`k>0`일 때 `k-1`). 한 루프에 섞지 말 것.
- **`in_range` 함수 호출 오버헤드**는 N ≤ 100, 스텝 ≤ 10^5이면 무시 가능. 10^7 넘어가면 인라인 고려.
- **Python 음수 모듈로는 양수로 돌아옴** (`-1 % 4 == 3`). 회전 공식에 `(d - 1) % 4`를 바로 써도 안전.
