# 행/열 독립 판정: 1차원 함수로 내리고 조기 return

## 언제 쓰나
행·열이 서로 영향을 주지 않는 격자 문제 (경사로/활주로, 스도쿠 줄 검사, 각 줄 회문 판정).
**판정 함수가 격자와 `r`을 받으면 안 된다** — 1차원 리스트 하나만 받게 만든다.

## 코드
```python
def is_ok(line, L):
    n = len(line)
    used = [False] * n
    for i in range(n - 1):
        ...
        if 안되는조건:
            return False        # ★ 기록해 두고 나중에 all() 하지 말 것
    return True

def solve(n, L, grid):
    # 전치만 하면 열도 같은 함수로 처리 — 회전([::-1]) 아님!
    return sum(is_ok(line, L) for line in list(grid) + list(zip(*grid)))
```
- `sum(bool)` = True 개수. 카운터 변수 불필요.
- 판정 단위가 1차원이면 `used`/`visited`도 `[False]*n` 하나면 끝 (n×n 불필요).

## 함정
- **"이어졌나"를 배열에 기록 → 마지막에 `all()`** 은 거의 항상 군더더기. 실패가 확정되는 순간 `return False`면
  배열·최종검사·카운터가 동시에 사라진다. (14890에서 판정부 35줄→24줄)
- **구간을 처리한 뒤 `i += L`로 점프하지 마라.** 점프하면 `i < n - L`, `i >= L - 1` 같은 **경계 가드가 필요해지고
  거기서 off-by-one이 난다.** `i += 1`로 한 칸씩 가도 이미 처리한 평탄 구간은 "차이 0" 분기로 알아서 통과한다.
  → 가드를 없애는 게 아니라 **가드가 필요 없는 구조로 만드는 것**이 정답.
- **대칭인 두 분기는 "무엇이 다른지"만 분기시켜라.** 내림/올림 경사로는 놓을 구간 `(lo, hi)`만 다르고
  검사(범위·겹침·평탄)는 동일 → `lo, hi` 계산만 2줄 분기하고 검사 루프는 하나.
  각 분기에 `all(...)`을 따로 쓰면 대칭성이 코드에서 사라진다.
- **전치는 `zip(*grid)`, 회전은 그것 + 뒤집기.** 행/열 독립 판정엔 전치만 필요. `[::-1]`을 붙여도
  합계는 안 바뀌어서 **틀린 줄 모르고 넘어간다** → 진짜 회전이 필요한 문제에서 습관이 발목 잡음.
- 한쪽 분기에만 검사를 넣고 "이쪽은 아직 안 지나갔으니 안전"에 의존하지 마라. 조건이 바뀌면 조용히 깨진다.
