# 다중 쿼리 최단경로 — 무엇을 루프 밖으로 빼는가

## 언제 쓰나
`Q`개의 (출발, 도착) 쿼리. 그래프(격자·간선 조건)는 **쿼리와 무관하게 고정**일 때.

## 핵심 3줄
1. **간선 판정은 전처리로 뺀다.** "여기서 저기로 갈 수 있나?"가 격자만으로 결정되면 쿼리 루프 안에 두지 않는다. → `adj[state] = [(next, cost), ...]` 한 번만 만든다.
2. **pop 즉시 종료.** 다익스트라는 pop 시점에 최단 확정. 도착 상태를 처음 꺼내면 바로 return.
3. **출발점별 메모이제이션.** 한 번의 탐색이 뱉는 `dist`는 *모든 목적지*의 답을 담고 있다. 같은 출발점 쿼리는 재사용.

## Q vs V — 전체쌍(APSP)로 갈지 판단
| 조건 | 선택 |
|---|---|
| `Q < V` | 쿼리별 탐색 (`Q`회) |
| `Q ≥ V` | 출발점 전부 미리 돌려 APSP (`V`회) + 조회 O(1) |

`V`는 **상태 수**(좌표만이 아니라 `좌표 × 부가상태`). 예: 50×50 격자 + 점프력 5단계 → V = 12,500. `Q ≤ 1000 < V`이므로 쿼리별이 유리.

## 함정
- **②③은 상충한다.** 조기 종료하면 `dist`가 미완성이라 메모이제이션에 못 쓴다. 둘 중 하나만 고른다 (중복 출발점이 많으면 메모, 적으면 조기 종료).
- **"도착은 부가상태 무관"이면 종료 조건에서 그 차원을 빼라.** `min(dist[r][c])`로 큐를 다 비우는 대신, `(r,c)`가 목적지인 아무 상태나 처음 pop되면 그게 답.
- 전처리 배열을 쿼리 루프 안에서 재할당하지 말 것. `dist`만 새로 만들고 `adj`는 공유.
