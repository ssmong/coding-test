# 백트래킹 템플릿 — 선택 → 재귀 → 되돌리기

## 언제 쓰나
"최단 몇 번?"이 아니라 **"모든 경우를 만들어보고 그중 최선/유효"**일 때. (BFS와 구분: [02-bfs-dfs.md](02-bfs-dfs.md) §7)

## DFS vs 백트래킹 (헷갈릴 때)
**백트래킹 = DFS + 되돌리기(상태 복구).** 별개 알고리즘 아니라 DFS의 응용.
차이는 딱 하나 — **`visited`를 되돌리느냐:**
| | 순수 DFS | 백트래킹 |
|---|---|---|
| 대상 | 이미 있는 그래프/격자 | 즉석에서 만드는 "선택의 트리" |
| visited | 영구 표시, **안 지움** (한 번 방문=끝) | 표시했다 **해제** → 다른 가지서 그 칸 **재사용** |
| 목적 | 순회·연결성·사이클 | 모든 후보 나열 + 가지치기 |
- **섬 개수 DFS**: `visited=True` 찍고 안 지움 → 순수 DFS.
- **N-Queen/14500 테트로미노**: 놓아보고 서브트리 돌면 `visited=False` 복구 → 백트래킹.
- ⚠️ **격자 완전탐색(각 칸 시작점)에서 되돌리기 누락** → 앞 경로가 뒤 시작점 탐색을 막음. 한 경로 끝나면 반드시 원상복구.
- 암기: "DFS는 갔다가 그냥 돌아온다, 백트래킹은 흔적까지 지우고 돌아온다."

## 심장: 빌리고-복구
```python
choose(x)          # 이 선택을 함 (상태 변경)
backtrack(다음)     # 더 깊이
unchoose(x)        # ★ 되돌리기 (상태 복구) — 이게 "무르기"
```
이 한 쌍이 백트래킹 전부. **복구를 빼먹으면** 형제 가지에 이전 선택이 새서 오답.

## 패턴 A — 개수로 가지치기 (14888 연산자)
같은 종류가 여럿이면 **개수만** 관리 → 자동 비구분(중복 가지 제거).
```python
for t in range(K):              # 선택 종류
    if cnt[t] == 0: continue
    cnt[t] -= 1                  # 빌림
    backtrack(idx + 1, 새상태)
    cnt[t] += 1                  # 복구
```

## 패턴 B — 인덱스 선택/미선택 (14889 N중 K 고르기, 조합)
```python
def bt(i, chosen):
    if len(chosen) == K:
        ... 평가 ...; return
    if i == N: return           # 다 봤는데 K 못 채움
    chosen.append(i); bt(i + 1, chosen); chosen.pop()   # i 선택 + 복구
    bt(i + 1, chosen)                                    # i 미선택
```
> 조합은 **`i+1`부터** 재귀해야 순서 중복 안 생김(같은 집합 두 번 X).

## 패턴 C — 개수 세기 (9663 N-Queen)
"몇 가지?"는 **각 호출이 자기 서브트리 개수를 return → 부모가 합산.** nonlocal/전역 불필요.
```python
def place(row):
    if row == N: return 1        # 한 행에 1개씩 다 놓음 → 완성 1가지
    total = 0
    for c in range(N):
        if 놓을수있으면:          # col[c], diag1[row+c], diag2[row-c+N-1] 로 O(1)
            표시(True); total += place(row + 1); 복구(False)
    return total
```
- **대각선 O(1) 충돌:** ↗/↙는 `row+col` 일정, ↘는 `row-col` 일정 → 불리언 배열 2개면 지난 퀸 `not in` 스캔 불필요. `row-col`은 음수 가능 → **`+(N-1)` 오프셋, 배열 크기 `2N-1`**. (방향 이름표는 바뀌어도 동작 동일 — 중요한 건 합/차 두 배열)
- **행 충돌 자동 해결:** `place(row)`가 한 행씩 내려가니 같은 행 체크 불필요.
- ⚠️ 누적값을 **int 인자로** 받아 `+=1` ❌ — 정수는 immutable이라 호출자에 반영 안 됨. **return 합산** 또는 `nonlocal`만 통함. (컨테이너 `[0]` 트릭도 되지만 지저분)

## itertools vs 직접 백트래킹
`itertools`는 표준 라이브러리라 항상 허용·관용적. **선택 기준:**
| 상황 | 도구 |
|---|---|
| 순수 "n중 k 고르기 / 순열 / 곱집합", **가지치기 없음** | `itertools.combinations/permutations/product` (재귀 오버헤드 없어 더 빠름) |
| **가지치기** 필요 / 부분상태 의존 분기 / 조기종료 (N-Queen, 연구소, 스도쿠) | **직접 백트래킹** |
- 핵심: itertools는 **전부 생성**해 중간에 못 걸러. 가지치기가 크면 백트래킹이 노드를 훨씬 덜 봐서 이김. 가지치기 없으면 itertools가 빠름(C레벨, 재귀 호출 오버헤드 없음).
- ⚠️ 성능 최적화 시 `sum(genexpr)`를 explicit Python `for`로 바꾸지 말 것 — 오히려 느려질 수 있음(측정으로 확인).
- ⚠️ 단, **순회 대상이 아주 작으면(≤10~20개) 반대로 뒤집힐 수 있음.** 9663/15686류에서 치킨집처럼 원소 수가 작은 컬렉션에 `min(genexpr)` 쓰면 제너레이터 생성 비용이 순회 절감분보다 커서, 명시적 `for` + 직접 비교가 실측상 약 2배 더 빠름(15686, N=50/houses=100/chickens=13 벤치). **"내장함수+genexpr가 항상 빠르다"가 아니라 컬렉션 크기가 클 때만 유리 — 작을 땐 측정 필수.**

## 가지치기: 상계(upper bound) 컷 — 백트래킹 속도의 심장
"남은 선택을 전부 **가장 낙관적으로** 채워도 현재 best를 못 넘으면" 그 가지 전체를 즉시 버림.
```python
if (K - depth) * max_gain + cur_sum <= best:   # 낙관적 상계
    return
```
- 뜻: "남은칸 × 격자최댓값 + 현재합"(가장 운 좋을 때 도달값)이 best 이하면 이 아래 전부 버림.
- 예: best=30, 지금 2칸 놓아 합=10, mx=9 → 남은 2칸 다 9여도 `10+2×9=28 ≤ 30` → 하위 트리 통째 컷.
- **14500 실측(500², CPython):** 상계 컷 없음 **67s** → 있음 **0.12~0.42s** (160~560배). 재귀 DFS도 이 한 줄로 CPython 통과 (PyPy·재작성 불필요).
- ⚠️ 낙관치는 반드시 **진짜 상한**. 과대평가는 안전(그냥 덜 자름), **과소평가는 정답 가지를 잘라 오답.** `max_gain`=값 전체 최댓값이면 안전.
- ⚠️ best가 **공유 상태**여야 컷 가능(가지 밖에서 갱신된 값을 봐야 함). 그래서 여기선 순수 return-합산보다 **누적자(`best=[0]`/nonlocal)** 가 자연스러움 — return형은 running-best를 못 봐 컷 타이밍이 어색.

## 연결영역 열거: "아무 칸에서나 자라기" (분기 모양을 특수처리 없이)
경로 DFS는 **마지막 칸**에서만 뻗어 직선만 만듦 → T처럼 **가지 분기** 모양을 놓침. **경로의 모든 칸에서** 확장하면 분기도 자연히 생성 → 크기 k 연결영역 전수.
```python
for x, y in path:                 # 마지막 칸만이 아니라 전부에서
    for dx, dy in DIRS:
        ... 미방문 이웃이면 path+[(nx,ny)]로 확장 ...
```
- 14500: 이거 하나로 5종(경로4 + T) 다 커버 → `path_t` 불필요.
- ⚠️ 트레이드오프: 같은 모양을 **여러 순서로 재생성**(중복 큼, branch~16). 실측 가지치기 없으면 **67s**(경로+T의 8.8s보다 느림). **반드시 상계 컷과 세트.**

## 함정
- **복구(`+= 1` / `pop()` / `visited=False`) 누락** — 가장 흔한 버그.
- **복구는 했는데 mark와 다른 인덱스** (9663: 마크 `diag1[r+c]` ↔ 복구 `diag1[c]`) — 복구 줄은 새로 치지 말고 **mark 줄을 복사해 True→False만** 바꾸기.
- **base case 위치:** 완성됐을 때(`idx==N`, `len==K`) 평가하고 `return`.
- 결과(max/min/count)는 **클로저나 인자**로 — 모듈 전역 피하기.
- 재귀 깊이 크면(>10⁴) `sys.setrecursionlimit`. 보통 코테 백트래킹은 얕음(N≤20).
