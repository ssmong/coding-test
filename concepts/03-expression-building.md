# 수식 만들기 4변형 — 규칙이 바뀌면 알고리즘이 바뀐다

## 판별 기준 (문제 읽을 때 이것부터 확인)
| 규칙 | 상태 | 접근 | 복잡도 |
|---|---|---|---|
| ① 왼→오 순차 (14888) | `acc` 1개 | 백트래킹 | 배치 수 × O(1) |
| ② 우선순위 존중 (`*`,`/` 먼저) | `(total, last)` 2개 | 백트래킹 (여전히 O(1) 전이) | 배치 수 × O(1) |
| ③ 괄호 자유, 숫자 순서 고정 | 구간 `dp[i][j]` | 구간 DP | O(N³) |
| ④ 숫자 순서도 자유 (24게임) | 남은 수 multiset | 두 개 뽑아 합치기 재귀 | O((N!)² 급) |

## ② 우선순위 존중 — 핵심은 상태 2개
"확정된 합 `total`" + "아직 곱해질 수 있는 마지막 항 `last`"로 쪼개면 **acc 하나일 때처럼 O(1) 전이**가 유지된다.
~~~python
# +x : total += last; last = x
# -x : total += last; last = -x
# *x : last *= x                  # 마지막 항만 커짐 → 우선순위 자동 반영
# /x : last = int(last / x)       # 0방향 절삭
# 끝  : answer = total + last     # ★ 마지막 last 더하는 걸 잊지 말 것
~~~
- `-3 * 4`는 `last = -3` → `last = -12`. `-(3*4)`와 같아 부호 자동 처리.
- `int(last/x)`는 `last`가 음수여도 0방향 절삭이라 `-(int(3/2))`와 일치 → [00-integer-division.md](00-integer-division.md).

## ③ 괄호 자유 — 구간 DP, 최대/최소를 **함께** 들고 간다
`dp[i][j] = (max, min)` / 분할점 `k`마다 `left op right` 4×(max,min 조합 4가지) 전부 시도.
- ⚠️ **최댓값만 추적하면 오답.** `음수 × 음수 = 큰 양수`, `max - min = 큰 값` 때문에 최솟값이 최댓값의 재료가 된다. 최대/최소 쌍은 세트.
- ⚠️ 14888처럼 **연산자 개수 제한이 붙으면 구간 DP가 깨진다** (상태에 종류별 잔여 개수가 들어가 폭발). 개수 제한 있으면 그냥 완전탐색.

## ④ 숫자 순서 자유 — "두 개 뽑아 하나로"
매 단계 남은 수에서 2개 선택 → 연산 → 결과를 다시 넣고 재귀 (N개 → N-1개). 비가환(`-`,`/`)은 순서 2가지 다 시도.
- N이 조금만 커져도 폭발 → **N ≤ 5** 정도에서만 성립.

## 함정
- ② 에서 **끝에 `last`를 안 더함** — 가장 흔한 실수. base case는 `total + last`.
- ② 를 ①처럼 `acc` 하나로 풀면 `*`가 앞 전체에 곱해져 오답.
- ③ 에서 최댓값만 DP → 음수 곱 케이스에서 틀림.
