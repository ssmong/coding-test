## 현재 강점 / 약점 요약

업데이트 일자: 2026-08-04

**강점**
- 완전탐색을 하위 경우로 정확히 분해 (14500: T-테트로미노가 경로DFS로 안 됨을 간파 → `path_dfs`(경로4종)+`path_t`(T 4회전) 분리; 15686 좌표 전처리). 정확성은 독립 브루트포스 스트레스로 검증 습관
- 완화(relaxation) 개념을 0-1 BFS(13549) → 다익스트라(1753)로 전이 — 첫 다익스트라 본체를 한 번에 정확히 (2000 랜덤그래프 전수일치). 알고리즘 핵심 이해도 양호
- 문제 지문의 동사 순서를 그대로 코드 순서로 옮기는 습관 (3190에서 "머리→벽→몸→사과/꼬리" 순 정확 이행)
- board 값을 상수로 추상화 (`EMPTY/APPLE/SNAKE`, `RIPE/UNRIPE/WALL`) → 분기가 바로 읽힘
- BFS 첫 문제(7576)에서 dist=-1 sentinel 통합 + 멀티소스 시작점 일괄 enqueue 정확히 적용
- 7576 재제출에서 행/열 경계·답추출·매직넘버는 self-교정 (단 `main()` 호출 누락은 2206서 재발 → 패턴 등재)
- 상태 차원 BFS(2206) 구조 자체는 한 번에 정확히 세움 — 상태축 분리·상태별 방문체크·조기종료 모두 의도대로

**약점**
- 리스트 생성 괄호 위치 (1753·1916·4485 3연속 → 이후 15686·9663·14500·13460서 무발생 = **해소 3/3**). `[X*n]`↔`[X]*n`. 처방 유지: 2D/배열은 항상 `[... for _ in range(n)]`. *해소됐지만 재발 시 즉시 재등록.*
- **🔴 변수 shadowing 재발 (4485 → 16234)** — 4485는 거리 `d`를 `for d in range(4)`로 덮어씀. 16234는 `for r, c in tmp:`가 **바깥** `for r in range(n)`의 `r`을 덮어씀. **핵심 오해: "for가 매 반복마다 다시 바인딩하니 괜찮다"는 안쪽 루프 변수(`c`)에만 참이다.** 바깥 변수(`r`)는 안쪽 루프가 도는 내내 오염된 채 남는다 → 어떤 칸이 BFS 시작점으로 아예 스캔되지 않고 조용히 오답(랜덤 3000케이스 중 172개 불일치). 처방: **리스트 언패킹 루프는 항상 새 이름**(`for tr, tc in tmp:`). 루프 변수 이름은 스코프 안에서 전역 유일하게.
- **정의만 하고 호출 누락 반복** (7576, 2206 `main()` 미호출 → 9663 변형 재발: `solve` 안에서 `place(0)` 호출 누락 → None 반환) — 작성 마지막에 "**정의한 함수를 전부 호출했나**" 확인 루틴. *출력이 빈/0/None이면 가장 먼저 의심*
- **BFS 거리 갱신 시 기준 칸 혼동** (2206 신규) — `dist[새칸]=dist[현재칸]+1`인데 우변까지 `nx,ny`로 끌려감. 규칙: "좌변=새 칸(nx), 우변=현재 칸(x)"
- **🔴 행/열 혼동 (6회, 현재 1순위 약점) — 특히 `nc = c + DR[d]` DR/DC 짝 오타가 14500→13460 연속.** `nr = r + DR[d]` 복붙 후 둘째 줄을 `DC`로 안 고침. **증상이 무서움: d=2/3(좌·우)서 `DR[d]=0`이라 제자리 → 무한루프(hang).** 처방: (a) 좌표 `(행 r, 열 c)` 단일 규약, (b) **`nr↔DR`·`nc↔DC`를 한 세트로 쓰고 복붙 직후 둘째 줄 `D_` 눈으로 확인**, (c) 방향 이동 첫 테스트에 **좌/우 이동 반드시 포함**(제자리 무한루프 즉시 발각).
- BFS 후 답 추출 검증 부족 — 시작점 dist 오해, early return 누락, `max(2D list)` 오용 등 (7576 1차)
- 상수/비교 일관성 — 상수 정의 후 매직넘버 직접 비교(7576 `==0`), `is` vs `==` 혼용(2206, small-int 캐싱으로 우연 통과). 같은 함수 내 비교 연산 통일할 것
- **재귀 종료·경계 처리 (외주수익 신규)** — ① base case의 `return`을 안쪽 `if`에 가둬 "갱신 안 될 때" fall-through→`works[N]` IndexError. **종료조건은 조건 성립 시 무조건 탈출.** ② 0-index 경계 `day+t<=N`(마지막 점유일=`day+t-1`, `day+t`=다음 빈날)을 `<N`으로 반복 혼동. 처방: "`day+t`는 인덱스가 아니라 다음 재귀가 볼 날, N까지 OK". ③ 스킵을 `for d in range(t)`로 여러 칸 열거하려다 `d=0`서 자기자신 재호출 무한재귀 — 스킵은 `day+1` 한 칸이면 재귀가 나머지 전개.
- **"기록해 두고 마지막에 검사" 구조를 습관적으로 씀 (보도블럭 신규)** — 실패가 확정되는 순간 `return False`면 되는데 `connected` 간선배열 + 최종 `all()`로 쓴다. 부작용이 큼: 배열을 유지하려고 `c += L` 점프가 생기고 → 점프 때문에 경계 가드가 생기고 → 거기서 off-by-one이 난다. **가드를 고치지 말고 가드가 필요 없는 구조를 고를 것.** 그리고 대칭인 두 분기는 다른 부분(`lo, hi`)만 분기시키고 공통 검사는 하나로.
- **🔴 백트래킹에서 상태를 "복사"로 관리 (이상한 체스 신규)** — undo가 안 되니까 `deepcopy`로 도피하는 반사가 있다. 근본 원인은 **마크가 bool이라 겹칠 때 되돌리면 남의 표시까지 지워지는 것**. 처방: `deepcopy`를 쓰고 싶어지면 그건 "상태 표현을 바꾸라"는 신호 — **bool → int 카운터(`+1`/`-1`)로 상쇄 가능하게** 만들면 복사가 통째로 사라진다. 정말 복사해야 해도 `deepcopy` 말고 `[row[:] for row in g]`.
- **정답이나 Python 상수로 TLE — 제출 전 상한 실측 미검증 (14889→14500 연속).** 재귀 대량호출이 함정: 14500 무컷 CPython 8.79s. 처방(우선순위): ① **상계 가지치기** — "남은칸×최댓값+현재합≤best면 return"이 재귀 그대로 두고 500² 8.79s→0.12s(측정). 완전탐색 최적화 1순위. ② 여전히 빠듯하면 PyPy3(실전 삼성은 CPython이라 못 기댐) 또는 루프-언롤. 제출 전 "셀수×셀당 호출수"로 임계(~10⁷) 먼저 가늠

### 2026-08-04
- BOJ 16234 / Codetree 계란틀 [gold-5] · BFS/연합 시뮬레이션 — 잘함: 연합=연결요소 판정 정확, `visited` enqueue 시점 표시, 방향벡터 `nr↔DR`·`nc↔DC` 짝 정확(행/열 패턴 무발생), `moved` 플래그로 종료조건 처리, 지적받은 두 건(`q.popleft()` 결과 미사용 → 시작칸 기준으로만 확장 / `/` → `//` 소숫점 버림)은 즉시 self-교정 / 놓침: **`for r, c in tmp:`가 바깥 `for r in range(n)`의 `r`을 덮어씀** — 안쪽 `c`는 range가 재바인딩해 복구되지만 `r`은 오염된 채 남아 일부 칸이 BFS 시작점으로 스캔되지 않음. 예제 5개는 전부 통과해서 안 잡히고, 랜덤 3000케이스 스트레스에서 172개 불일치로 발각 (반례: `5 9 22 / 50 21 30 38 60 / 30 24 20 16 51 / 12 45 50 16 6 / 37 20 34 32 57 / 22 47 29 19 39` → 정답 3, 오답 4) / 교훈: **예제 통과 ≠ 정답. 조용히 칸을 건너뛰는 버그는 작은 예제에서 안 드러난다 — 독립 레퍼런스 대조 스트레스가 유일한 발견 수단** / 태그: 변수-shadowing-바깥루프, 예제통과-함정, 스트레스테스트-필수

### 2026-08-01
